# Known limitations

Celenne Studio 0.3.0 is a preview. This page lists what is missing, partial or approximate. In the app, unfinished commands are marked **Coming Soon** and explain themselves when used.

## Partial or approximate

- **Camera RAW (CR2, CR3, NEF, ARW, RAF, ORF, RW2, PEF, SRW and others):**
  - **How:** LibRaw unpacks the sensor data and Celenne develops it with the same stages as DNG
    (below).
  - **Accuracy:** colours match LibRaw's own development of the same data within ΔE 0.3 on the test
    samples, for one camera of each major brand.
  - **Crop:** Photoshop trims a few more edge pixels on some cameras (Nikon D750, Pentax PEF, Samsung
    NX500: up to 16 px), using Adobe's own camera tables. The Fujifilm X-T3 comes out 5 rows
    shorter.
  - **Speed:** a 24-megapixel file opens in about 1.5 s; Fujifilm X-Trans files take about 3 s.
  - **X-Trans detail:** X-Trans sensors use a simple demosaic, so fine detail is softer than in
    Photoshop.
  - **Unsupported:** files LibRaw cannot read (such as Nikon High Efficiency NEF, or very new
    cameras) open as their embedded JPEG preview, with a message.
- **Camera RAW (DNG):** as-shot white balance, baseline exposure, Malvar–He–Cutler demosaic (Bayer) or a neighbourhood average (other CFA patterns such as X-Trans), camera colour matrix, 16-bit ProPhoto RGB output with a neutral (linear-to-gamma) tone response. Not applied: DNG opcode lists (lens corrections, gain maps), DCP camera profiles, highlight reconstruction. Lossy (JPEG) DNG and floating-point DNG are not decoded (the embedded preview is offered instead). There is no Camera Raw dialog; adjust after opening.
- **Type on a path:** click a path with the Type tool; drag the start (filled) and end (hollow) markers, or use Start / End / Flip / Detach in the options bar. Photoshop path text is read with its path, markers and flip (verified against a Photoshop-saved file: Celenne's layout of the same text matched Photoshop's rendering to within 1 px) and becomes editable; glyph spacing after an edit follows the platform text engine. Celenne writes Photoshop's own path-text data: Photoshop opens such files without a prompt and keeps the text on its path; its layout matches Celenne's within about 2 % (IoU 0.98).
- **CMYK documents** store each layer as two plates (C'M'Y' and K', inverted ink as in Photoshop), so they use about twice the memory of RGB. Painting, fills, gradients, text, shapes, transforms, filters (run per plate) and Levels / Curves (with a Black channel) work on the inks directly. Colour adjustments (Hue/Saturation, Color Balance, …) act on the C, M, Y plates like Photoshop's CMYK mode and leave black untouched. Content-aware fill, Remove and Spot Healing match patches on the image's appearance and copy the real inks of the matched patches (black included); Generative Fill with a cloud provider and RGB-only plugin tools return RGB, so only the pixels they change are separated by the CMYK profile. Plugin tools that declare `nativeColor` work on the inks directly. Painting a colour channel on its own (single-channel targeting) is not available. PSD / PSB, TIFF, JPEG and PDF are written and read as CMYK (PNG / WebP cannot hold CMYK and get the sRGB appearance).
- **The built-in CMYK profile** (“Celenne Coated CMYK (approximate)”, medium GCR, 300 % ink limit) is a model of coated offset printing, not a measured press profile. Load your printer's profile in Preferences ▸ Color Management for real print work.
- **Lab documents:** tools and filters work through an exact RGB view of the L a b values; blend modes other than Normal and layer effects are evaluated in RGB. TIFF (CIE Lab) and PDF (Lab colour space) keep Lab; JPEG and PNG get the sRGB appearance.
- **Duotone** documents are Grayscale data plus up to four inks (name, colour, 13-point curve), exactly as Photoshop stores them. Files from Photoshop are shown with Photoshop's own stored rendering until their inks are edited. After an edit the inks are mixed with Photoshop's model as measured against Photoshop 26.5's renderings of 73 specifications (1–4 inks, random colours and curves, computed and custom overprints) plus the psd-tools sample: 0.39 ΔE on average, 1.3 ΔE at most, which is about the rounding of the stored 8-bit rendering. Overprint colours are editable (Duotone Options ▸ Overprint Colors…); changing an ink's colour recomputes the overprints that use it. Photoshop takes the dot gain from its Color Settings (Spot, 20 % by default) rather than from the file; Celenne's equivalent is Preferences ▸ Color Management ▸ Spot dot gain. Custom inks (PANTONE etc.) are shown with the Lab colour Photoshop stores for them; their colour book data is kept unchanged. Image formats other than PSD receive how the inks print (sRGB).
- **Multichannel** documents have no layers (as in Photoshop): each channel is an ink you paint on by selecting it in the Channels panel. Inks are displayed with the overprint model; opaque (solid) spot inks cover like Photoshop's solidity. Converting to RGB / CMYK is exact for C M Y (K) channel sets, otherwise it uses how the inks print.
- **Spot channels** are printed over the image on screen with their ink colour and solidity (eye in the Channels panel). Exports to image formats leave them out, as Photoshop does. **Merge Spot Channel** (right-click the channel) prints the ink into the image: unlike Photoshop it does not flatten — the ink becomes Color Fill layers at the top, masked by the channel, which reproduce the spot display exactly in RGB; in Grayscale the ink becomes its gray value. In CMYK the ink is converted to CMYK and mixed there, as in Photoshop, so inks outside the CMYK gamut (fluorescent, metallic) print duller than their preview. Not available in Lab, Duotone or Multichannel documents.
- **Warp Text** is re-rendered by Celenne after an edit; the warp curves approximate Photoshop's. Vertical text follows Photoshop's layout (upright characters, columns right to left; IoU 0.997 with Photoshop's outlines).
- **Indexed Color / Bitmap** are 8-bit, single-layer modes (as in Photoshop). Adding layers is refused with a message; painting and filters work and their result is snapped to the color table (nearest color, no dithering) or to black and white. Bitmap conversion keeps the document resolution (no output-resolution change).
- **Match Font** compares the sample with the fonts the platform exposes (installed fonts via Local Font Access, otherwise the bundled list). It ranks shapes of the typed text; it does not recognise text.
- **Generative Expand / Generative Fill** with the local provider use content-aware fill (PatchMatch), not a generative model. Connect an AI provider (Preferences ▸ AI) for generative results.
- **GPU compositing** (WebGPU renderer) covers pixel, text, shape, smart object and fill layers, all blend modes, opacity / fill, masks and vector masks, Blend If, channel restrictions, isolated and pass-through groups, clipping groups and every adjustment type, in RGB, Gray, CMYK and Lab at 8, 16 and 32 bits. Tiles that contain layer effects or knockout, Color Lookup tables larger than 65³, and the single-channel, overlay, quick-mask, soft-proof and Duotone / Multichannel / spot-ink views are composited on the CPU. The first GPU render compiles the shaders (a few seconds on older drivers). Changing the renderer takes effect after a restart.
- **GPU previews** cover Gaussian Blur, Box Blur, Unsharp Mask and Image ▸ Adjustments (not smart-filter edits or Lab documents, which preview on the CPU). Applying a filter or adjustment, saving and exporting always run on the CPU.
- **Scratch disk** pages history-only tiles to disk in the desktop app. In the browser build there is no scratch disk and memory is bounded by the history-state limit.

## PSD fidelity

See [PSD_COMPATIBILITY.md](PSD_COMPATIBILITY.md) for the full matrix. The main caveats:

- **Verified against Photoshop.** A corpus of 170 files built by Photoshop 26.5 itself (`tests/fixtures/photoshop/corpus`, see its README) covers every blend mode, fill opacity, groups, masks, clipping, knockout, all adjustment types, fill layers, smart objects, layer effects, 16/32-bit, Gray, CMYK and Lab. Celenne's render is compared with Photoshop's stored composite on every test run: 125 files match within 2/255 and 148 within 2/255 for 99 % of pixels. The first 153 files also go the other way: saved by Celenne, opened and re-saved by Photoshop with the same layers and the same look. The 59-layer real design file verified earlier also matched within 4/255.
- **Photo adjustments** are matched to Photoshop on the full RGB cube (largest difference on 99 % of colours within 2–5/255). Remaining gaps: Vibrance is Photoshop's measured output interpolated between ten levels (up to 5/255 between levels, 10 for strong Vibrance and Saturation together on saturated colours); Photo Filter with Preserve Luminosity (up to 9 on saturated colours at the gamut edge); Hue/Saturation with both a colour range and a master edit (up to 18 on pastel reds, 99 % within 5) and very narrow colour ranges (up to 10). Photo Filter's colour maths assumes an sRGB document.
- **Not yet matched** (measured gap, largest difference on the test image): 8-bit Lab documents with blend modes other than Normal (41; 16-bit Lab matches), Satin (11), and Dissolve's random pattern. Layer effects match within 1/255 on straight edges; on curved anti-aliased edges a few pixels of strokes, spread glows and chisel / emboss bevels still differ.
- **Layer effects** are rendered by Celenne's own implementation, modelled on Photoshop's measured behaviour (tent-shaped blurs for shadows and glows, Photoshop's bevel height fields and lighting). Contours other than Linear and the Chisel Soft technique are approximated. Parameters round-trip exactly.
- **Text** is drawn by Celenne's own text engine (HarfBuzz shaping, the font's own outlines) once the installed fonts are available; while the engine or a font is still loading, the browser's text renderer draws it and the layer is redrawn when the font arrives. Opened Photoshop text keeps Photoshop's stored pixels until it is edited. After an edit, paragraphs that did not change keep Photoshop's exact line breaks (and word spacing, and glyph positions for optical kerning and faux bold); an edited paragraph is re-flowed by Celenne's composer, which follows Photoshop's Single-line composer exactly on the test corpus; for the Every-line composer it uses an approximation that breaks 44 % of test paragraphs exactly as Photoshop (70 % of lines), so an edited Every-line paragraph can break differently. Anti-aliasing: None and Strong follow Photoshop's measured behaviour; Smooth, Crisp and Sharp are plain coverage, while Photoshop also snaps stems of small text to the pixel grid (hinting), so small text looks slightly softer than in Photoshop. Underline and strikethrough are not drawn on vertical text or text on a path yet. Celenne's own composer and optical margins are Celenne-only: Photoshop lays such paragraphs out with its Single-line composer. Hyphenation is English (US) only. Thai is broken into words with a dictionary, which differs from Photoshop's word list on a few words (for example "ทดลองใช้"). Celenne writes Photoshop's text data (`Txt2`) for horizontal and vertical text and type on a path, so Photoshop opens edited, new and copied text layers without asking to update them; for text with OpenType features or variable-font axes it cannot yet, and Photoshop asks to update the layers when such a file is opened.
- **Photoshop smart filters, vector (PDF/AI) smart objects, video/timeline, 3D, artboards, layer comps and annotations** are shown from stored pixels and preserved, but not editable. Artboards are edited as groups.
- **CMYK and Lab** PSDs open natively and save back in their own mode (8/16-bit). Text and shape colours are written with exact CMYK / Lab values; Photoshop re-renders type with its own composer when the text is edited.
- *Convert to Profile* converts pixels and every stored color (fill layers, text, shapes, effects, Photo Filter / Black & White / Gradient Map colors), but tonal adjustment layers (Curves, Levels, Hue/Saturation, …) keep their settings and so act slightly differently in the new space.

## Tools and editing

- **Selection AI (local)** uses classical algorithms (color models, flood fills, guided filter), not learned segmentation. Results are good on clear subjects and weaker on busy scenes.
- **Content-aware fill** uses PatchMatch. Large or structured regions can show repetition.
- **Tablet input** uses Pointer Events (pressure, tilt, twist) through Windows Ink. WinTab-only drivers are not supported.
- **Plugin filters** have no live preview and cannot be used as smart filters. Plugin tools run when the stroke ends (no live preview while dragging).
- **Macro replay:** "reorder layer" steps replay within the active layer's own parent (layer ids are document-specific). Assign/Convert Profile steps replay only for built-in profiles.
- **Large documents:** PSB up to 300,000 px is supported by the container, but opening is limited by the memory budget (Preferences ▸ Performance).

## Distribution

- The release pipeline can code-sign (see [RELEASING.md](RELEASING.md)), but no certificate is configured yet, so installers built today are **unsigned**. Windows SmartScreen warns on first run. A new certificate also starts without SmartScreen reputation, so the warning can still appear for a while after signing begins.
- **Auto-update** works only in builds made with `npm run release`, and needs an update address (`celenne.release.local.json`) and the release key. Builds from `npm run dist` say so under Help ▸ Check for Updates.
- Releases are **setup only**. A portable copy from an earlier local build cannot update itself; it tells you about a new version and links to the setup download.
- **Error reports** are kept on the computer until a report destination (Sentry or GlitchTip DSN) is set in `celenne.release.local.json`. Native crash dumps are never uploaded.
- The **Microsoft Store package** (`npm run release -- --store`) is configured but has not been built yet. Microsoft's packaging tool needs the Windows SDK, which is not installed on the build PC.
